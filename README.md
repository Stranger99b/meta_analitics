# GoTrips Analytics — Meta Ads · Instagram · Threads

Автоматическая аналитика для туристической компании **GoTrips** (@gotrips_by):
платная реклама Meta Ads **и** органика Instagram/Threads. Отчёты собираются по
расписанию и отправляются в Telegram — рекламные в личный чат, органические
(Instagram и Threads) — фирменным **PDF** в группу, тему «Отчет».

Данные берутся из Meta Marketing API, Instagram Graph API и Threads API;
качественные выводы генерирует ИИ (Qwen с фолбэком), вёрстка PDF — reportlab.

---

## Возможности

### 1. Meta Ads (платная реклама)
- **Ежедневный** отчёт по рекламе (21:45, `run_ads_daily.py`): расход и лиды за
  вчера, CPL, сравнение с нормой за 7 дней, тревоги (расход без лидов, скачок
  CPL), органика рядом для контекста → Telegram.
- **Еженедельный** отчёт (Пн 04:00): WoW-сравнение двух недель, стратегические
  выводы + блок атрибуции «расход Meta → лиды Salebot».
- Мониторинг подписчиков Instagram (снимок по дням).

> **Откуда берутся лиды.** С ~23.08.2026 Meta перестала отдавать в Marketing API
> метрики переписок — `onsite_conversion.messaging_conversation_started_7d` и
> соседние (ограничения на выдачу данных). Расход, показы и клики приходят
> по-прежнему. Поэтому «начатые переписки» считаются на нашей стороне: у клиента,
> пришедшего с рекламы, Salebot заполняет `instagram_ads_data` (JSON с `ad_id` и
> `ad_title`), по нему и джойнимся с расходом — модуль `salebot_leads.py`.
> В дневном отчёте есть блок «Что отдаёт Meta»: как только метрика вернётся,
> он это покажет.

Старый `run_daily.py` (AI-аудит + выгорание креативов, был в 03:00) остаётся
отключённым — новый дневной отчёт намеренно лёгкий.

#### Что означает каждая строка дневного отчёта

**«Лид» = НОВЫЙ клиент Salebot, у которого дата создания равна отчётному дню
и заполнено `instagram_ads_data`.** Один клиент = один диалог. Это и есть
знаменатель CPL: сколько реально стоил приведённый рекламой диалог.

| строка | что показывает | зачем |
|---|---|---|
| 💸 Расход · лидов · CPL | расход дня ÷ новые диалоги за день | базовая цена диалога |
| *норма за 7 дней* | те же величины за 7 дней ДО отчётного | база сравнения, отчётный день в неё не входит |
| 📅 За 7 дней | скользящая неделя ВКЛЮЧАЯ отчётный день | дневной CPL при 2-5 диалогах шумный: один клиент двигает его на десятки долларов. Решения по бюджету принимать по этой строке |
| 🖱 Из 100 кликов в диалог | новые диалоги ÷ клики × 100 | отделяет падение спроса от поломки связки: при падении спроса проседает CTR, при поломке клики есть, а диалогов нет |
| 💎 Качество аудитории | (сохранения + реакции + комментарии) на 1000 показов | эти действия Meta считает честно и не режет; низкоинтентная аудитория их не совершает. Проседает раньше, чем это станет видно по лидам |
| 🔁 Старые клиенты с меткой | пришли раньше, но писали в этот день | без них «2 лида за день» выглядит ошибкой (06.09.2026: 2 новых против 15 старых). В CPL НЕ входят: метка `instagram_ads_data` — постоянный атрибут клиента, а не сегодняшний клик |
| 🌱 Органика | новые клиенты без метки рекламы | если органика падает вместе с рекламой — проблема шире Meta |
| ⚠️ Тревоги | см. пороги в коде | расход без лидов, CPL >2× нормы, лиды <½ нормы, конверсия кликов <½ нормы, качество <60% нормы, органика упала вместе с рекламой |
| 🔌 Что отдаёт Meta | показы, клики, CTR + какие метрики переписок вернулись | покажет момент, когда Meta восстановит выдачу |

**Ориентиры (посчитаны 08.09.2026):** до обвала, 01–21.08.2026, CPL держался в
коридоре **$4–8** без единого выброса, 32–77 диалогов в день. После, 25.08–07.09,
CPL **$23** в среднем при разбросе $12–128. Стабильный коридор — признак
работающей оптимизации; хаотичный разброс при том же бюджете — признак того,
что оптимизацией никто не управляет.

#### Несколько рекламных кабинетов

Кабинеты перечисляются в `.env`: `META_AD_ACCOUNTS=act_123:Беларусь,act_456:Личный`
(метка — как кабинет подписан в отчёте). Без этой переменной берётся один кабинет
из `META_AD_ACCOUNT_ID`, как было раньше. Расход и показы суммируются, в разбивке
по кампаниям видно кабинет, а в блоке «Что отдаёт Meta» — строка по каждому, чтобы
заметить, если метрика переписок где-то оживёт.

Понадобилось 11.09.2026: после GDPR-ограничения старый кабинет остановили и бюджет
ушёл в два новых, а отчёт по одному кабинету стал показывать расход $0 при живых лидах.

**Лид привязывается к кампании по `ad_id`, а не по номеру «№XXX» из названия.**
Номера в разных кабинетах повторяются (в обоих новых кампании назывались №001), и
разбор по номеру склеивал разные кампании в одну строку. Имя кампании берётся
у самой Meta через карту `ad_id → кампания`, построенную по инсайтам за неделю.

Остаётся один случай, где имя всё же важно: Salebot иногда присылает `ad_id` варианта
плейсмента (имя оканчивается на `_Group_1`), которого у Meta нет как объекта —
прямой запрос отвечает «does not exist». Такой лид привязывается по номеру из
названия объявления, а если номера нет, попадает в строку «объявление без №XXX
в названии» и в тревоги. Отсюда правило: **номер должен быть в названии ОБЪЯВЛЕНИЯ**,
а не только кампании — Salebot присылает именно имя объявления.

#### Секреты в данных и логах

Токен Meta утекает двумя путями, оба закрыты:

1. *Ошибка → Telegram.* `requests` цитирует в тексте HTTPError весь URL, а токен
   едет в query-строке. Чистится в `send_telegram.redact()`, которая вызывается
   внутри `send_message` — в единственной точке выхода.
2. *Успешный ответ → диск.* Meta кладёт `access_token` в ссылки постраничной
   навигации (`paging.next`), и они сохраняются вместе с ответом. Чистится
   в `secrets_scrub.scrub()`, которой обёрнуты все 15 `json.dump` в `scripts/`.

Голый `EAA…` намеренно НЕ вычищается: такие фрагменты встречаются внутри CDN-ссылок
Facebook на фото (параметр `_nc_oc`) и токенами не являются — правило «резать всё,
что начинается на EAA» испортило бы рабочие данные. Чистятся только явные
`access_token=`, `input_token=`, `client_secret=` и токены Telegram-ботов.

**Известная погрешность ~0.4% в меньшую сторону.** Salebot иногда дописывает
метку рекламы с задержкой; если клиент сразу замолчал и в следующие выгрузки не
попал, в наших данных он останется органикой. Проверено сверкой с ручной
выгрузкой из интерфейса Salebot за 20.08–07.09: 654 клиента, расхождение 1.

### 2. Instagram — органика
- **Недельный** и **месячный** дайджесты в PDF: охваты, просмотры, вовлечённость,
  прирост подписчиков (WoW / MoM), топ публикаций с кликабельными ссылками, детектор
  «залетевшего» контента (≥2× среднего).
- **Аналитика сторис**: ежедневный снимок (API отдаёт только активные <24 ч),
  метрики просмотров/охвата/визитов профиля/подписок, **разбивка навигации**
  (вперёд/назад/закрыли/ушли) и метрика **удержания**. У каждой сторис — ID
  «дата #номер (время)» для поиска в архиве.
- **Сравнение типов контента** (рилс / посты / сторис) — что эффективнее и сколько
  какого контента нужно.
- Вся история сторис заливается в **Google Sheets** (ссылка в отчёте).

### 3. Threads — органика
- **Недельный** и **месячный** дайджесты в PDF в том же стиле: просмотры, лайки,
  ответы, репосты, цитирования, прирост подписчиков, топ постов со ссылками.

### Оценка работы SMM (в каждом дайджесте)
- **Прозрачная рубрика** (`smm_score.py`): балл 0–100 → 1–10 по 6 критериям — рост
  охвата/просмотров, вовлечённость (ER), прирост подписчиков, работа со сторис,
  активность (постинг), виральность. Гибрид норм и динамики; считается **кодом**
  (стабильно), выводится таблицей в PDF; критерии без данных исключаются.
- **Норматив SMM (KPI недели)** в конфиге `smm_score.py`: Reels 2, Карусели 1, Посты 1,
  Сторис 6/7 дней, Threads 4. В каждом дайджесте — блок **«План vs Факт»** (✓/✗), а балл
  за активность считается по МИКСУ (reels+карусели+посты отдельно) — алгоритм ловит именно
  нужные действия. Норматив продублирован в ресерч-плейбуке.
- **AI поясняет** рассчитанный балл (Qwen `--role long`, с ретраем/проверкой полноты
  и фолбэком) + рекомендации. Есть и в недельных, и в месячных, IG и Threads.

### Стратегия/план для SMM (обновляется ежемесячно)
- `research_pdf.py` + `run_strategy_monthly.py` — «ПЛАН SMM на месяц» в фирменном PDF,
  **двухслойный**: динамический слой (диагноз месяца из данных — формат-лидер, MoM-динамика,
  топ-темы; предложения по корректировке KPI; фокус от Qwen) + стабильная методичка
  (тренды 2026, хуки, воронка, пиллары). **Cron 1-го числа 10:20 → тема «Отчет»**.
  KPI-нормы фиксированы в конфиге; документ только предлагает корректировки (решает человек).
  Без данных `research_pdf.build()` даёт статический плейбук.

### Фирменные PDF
- Салатовый бренд-цвет **#73D700** (с gotrips.by), цветные emoji (Twemoji),
  кликабельные ссылки на посты/рилс, таблицы для сторис и сравнения типов, номер
  недели/месяца в шапке и имени файла (напр. `№34_2026_IG_недельный_дайджест.pdf`),
  вёрстка под мобильный экран. Кириллица — DejaVuSans.

## Расписание (cron)

| Отчёт | Когда | Куда |
|---|---|---|
| Meta Ads дневной (реклама+лиды) | 21:45 | личный чат |
| Meta Ads недельный | Пн 04:00 | личный чат |
| Instagram недельный (PDF) | Пн 10:00 | группа, тема «Отчет» |
| Threads недельный (PDF) | Пн 10:05 | группа, тема «Отчет» |
| Instagram месячный (PDF) | 1-го, 10:15 | группа, тема «Отчет» |
| Threads месячный (PDF) | 1-го, 10:10 | группа, тема «Отчет» |
| Снимок сторис + Google Sheets | 07:00 / 15:00 / 23:00 | — |

Ручной запуск — тот же скрипт напрямую; месячные принимают аргумент `YYYY-MM`
для перегенерации за конкретный месяц. Дневной отчёт по рекламе принимает
`--date YYYY-MM-DD` и `--dry-run`.

**Почему дневной отчёт в 21:45.** Выгрузка Salebot за день D покрывает окно
21:00 D-1 → 21:00 D и стартует в 21:05 (идёт 10-15 мин). Клиенты, пришедшие
вечером, попадают только в дамп следующего дня, поэтому отчёт за вчера ждёт
сегодняшнюю выгрузку — иначе теряется 3-6 лидов в день. Часовой пояс рекламного
кабинета (Europe/Moscow) совпадает с часовым поясом выгрузок, даты сходятся.

## Настройка

Переменные в `.env` (см. `.env.example`):
- `META_ACCESS_TOKEN` — токен Meta (Instagram Graph + Ads), 60 дней; продлевается
  `exchange_token.py`. Права: `ads_read`, `business_management`, `instagram_basic`,
  `instagram_manage_insights`, `pages_read_engagement`, `pages_show_list`.
- `THREADS_ACCESS_TOKEN` / `THREADS_USER_ID` — отдельный токен Threads API
  (`exchange_threads_token.py`, права `threads_basic`, `threads_manage_insights`).
- `META_AD_ACCOUNT_ID`, `META_APP_ID`, `META_APP_SECRET`.
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`; `IG_TG_CHAT_ID`/`IG_TG_THREAD_ID` и
  `THREADS_TG_CHAT_ID`/`THREADS_TG_THREAD_ID` — группа и тема «Отчет».
- `GSHEETS_CREDENTIALS` — путь к service-account JSON (Google Sheets).

```
pip install -r requirements.txt
```

## Заметки
- Instagram Stories API отдаёт только активные сторис (<24 ч), поэтому нужен
  регулярный снимок; метрики растут все 24 ч → снимок 3×/день + dedup по макс.
  просмотрам.
- Instagram account insights ограничены окном 30 дней — месячные метрики собираются
  по частям и суммируются.
- Threads API отдельный от Facebook/Instagram (свой токен, база `graph.threads.net`).
